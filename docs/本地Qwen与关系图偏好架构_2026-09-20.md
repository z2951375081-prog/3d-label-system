# 本地 Qwen3-VL 与关系图 Transformer-MoE 布局模型（2026-09-20）

## 当前实现

项目的基础布局学习已升级为 FNN-关系图 Transformer-四专家 MoE：一个物体的全部固定标签组成一张图，每个标签是节点，标签之间的空间与语义关系是有向边。

节点输入为 51 维：16 维三维标签/物体几何，加主、右、左、上、下五个视角各 7 维投影特征。边输入为 13 维：相对锚点 xyz、相对初始中心 xyz、锚点距离、中心距离、共享来源部件、共享目标组，以及三轴标签尺寸对数比例。

网络首先采用 51→64 节点编码，再经过一层 64→128→64 残差 FNN 提取标签节点内部信息，然后进入两层关系消息传递。每层同时学习自身节点变换、邻居节点变换和边特征变换，按目标节点聚合全部入边，用于提取局部标签关系。随后一层缩放点积 Transformer 自注意力在完整标签集合上提取全局依赖，并通过残差连接与 64→128→64 FFN 更新节点表示。

Transformer 输出进入可学习的逐节点 Softmax MoE 路由器。当前四个专家分别命名为 geometry、relations、multiview_style、global_context，每个专家具有独立的 64→32→6 输出头；最终输出是四个专家六维预测的软加权和，而不是硬选择。前置 FNN、路由器、Transformer 注意力投影和全部专家均通过同一个监督损失反向传播，并在模型报告中记录参数更新量、FNN 消融输出差异、平均门控权重、归一化熵和主导专家比例。

六维输出为初始标签中心的残差 xyz 和面板尺寸的对数比例 xyz。最终仍由五视角确定性能量与模拟退火保证重叠、越界、遮挡、穿模、引导线和双目安全。

基础监督目标为确定性五视角安全优化器产生的布局教师。人工标注继续固定标签数量、ID、文字、锚点和语义关联，但人工调整后的最终中心/尺寸不进入网络输入。这样图网络负责学习关系几何和安全初值，视觉 LLM 负责安全候选之间的美学风格偏好。

## 本地视觉偏好

项目已删除 OpenAI Responses、Chat Completions、第三方 URL 和 API Key 接入。视觉评分只允许访问本机回环地址上的 Ollama：

- 服务：http://127.0.0.1:11434/api/chat
- 模型：qwen3-vl:4b-instruct
- 模型摘要：Qwen3-VL 4.4B、Q4_K_M、视觉能力
- 请求：原始模型图加主/右/左/上/下五视角，共六图
- 输出：JSON Schema 约束的十四维 1–5 分
- 上下文：num_ctx=32768
- 安全：不需要凭据，只允许 localhost/127.0.0.1，不向外部上传图片

十四维中，文字清晰、覆盖、标签重叠、物体遮挡、穿模、引导线、多视角、双目和尺寸一致性用于安全诊断；人工风格相似、空间平衡、视觉层级、构图和谐和整体美感用于 chosen/rejected 与 12→32→1 奖励模型训练。奖励模型只在确定性安全门控通过的候选中重排。

## 命令

~~~powershell
ollama list
npm run train:layout -- --epochs 5 --learningRate 0.001 --weightDecay 0 --hiddenDim 64 --preGnnFnnLayers 1 --messageLayers 2 --transformerLayers 1 --expertCount 4 --seed 17
npm run select:multiview -- --model experiments/layout_model_provenance_safe_candidate.json --previous experiments/layout_model.json
npm run test:scoring
npm run test:preference
~~~

v7 从已验证 v6 热启动，保留节点编码、GNN、Transformer 与三个已有专家，新增近恒等残差 FNN 和 global_context 专家。激活除要求参数发生训练更新外，还要求移除 FNN 后的验证输出差异大于阈值，以证明前置 FNN 真正参与推理。训练写入候选文件，只有 val 门控通过才允许替换活动模型；test 只用于最终确认。
