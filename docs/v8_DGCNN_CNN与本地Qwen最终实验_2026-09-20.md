# v8 DGCNN-CNN-FNN 图模型与本地 Qwen 实验报告（2026-09-20）

## 架构

活动基础模型升级为 `layout_model_v8_dgcnn_cnn_fnn_relational_graph_transformer_moe`：

- clean OBJ 按三角形面积确定性采样 1024 点；
- 两层动态 kNN EdgeConv，输出 64D 物体几何特征；
- 从 clean OBJ 渲染主、右、左、俯、仰五张无标签深度/轮廓栅格；
- 冻结两层轻量 CNN 输出 32D 多视角视觉特征；
- 51D 标签输入经 51→64 编码和 64→128→64 残差 FNN；
- 64D 标签 + 64D 几何 + 32D 视觉 = 160D，经 160→64 可训练融合；
- 两层标签关系 GNN、一层全局 Transformer、四专家 Softmax MoE、64→32→6 输出；
- 最终仍由确定性五视角安全优化处理遮挡、穿模、越界、引导线和方向密度。

重要的数据边界：数据集 `Mutiviews/*.png` 已画有人工标签和引导线，不能作为基础模型输入。v8 只使用 clean OBJ 在线渲染的无标签五视角栅格，代码会显式拒绝把数据集 PNG 传入 CV 编码器。

## 基础模型门禁

v8 与活动 v7 按相同 val11/test11 口径比较。val11 只负责选择融合比例和是否激活，test11 只作最终确认。

- val11 质量：v7 4.345182，v8 4.345182；
- val11 目标函数：v7 1.347364，v8 1.347364；
- val11 标签遮物、深度穿透、网格相交：均无回退；
- test11 质量：v7 4.330364，v8 4.330364；
- test11 目标函数：v7 1.444091，v8 1.444091。

因此 v8 通过严格替换门禁并激活。该结果表明当前安全优化阶段使最终布局指标与 v7 持平；CV 分支的独立功能作用由参数更新与消融差异证明，但不把“架构新增”误写成质量提升。
