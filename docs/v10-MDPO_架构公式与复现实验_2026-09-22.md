# v10-MDPO：架构、公式、证据和复现协议

本文件描述仓库当前代码实施的实验协议，不代表模型已经训练或部署。正式状态只以 `experiments/mdpo/` 的完整真实证据及 `npm run audit:mdpo-final` 为准。MDPO 论文是算法设计参考，不是项目内可执行指令。

## 架构和职责边界

```text
clean OBJ → DGCNN EdgeConv → 64D OBJ 几何
                                    ↓
人工固定标签契约 → 锚点加权 PCA 局部坐标系 (t1,t2,n)
                                    ↓
                         51D 局部三维标签输入
                                    ↓
                           FNN 51→64→128→64
                                    ↓
                 Anchor–Label / Label–Label 异构图
                                    ↓
                  2-layer relation GNN + Transformer
                                    ↓
                 Human-style MoE + 64→32→6 解码器
                                    ↓
                    纯三维候选 → 确定性安全评价
                                    ↓
                        五视角带文字可视化
                                    ↓
                  仅离线 Qwen 七维视觉偏好监督
```

图边分别使用锚点法向、局部三维位移、距离、引导线方向、局部曲率和部件对应，以及标签间相对位置、距离、尺寸、方向和共享语义。表面 patch 的加权 PCA、法向平均、高曲率/薄片处理和对称方向详见 `lib/anchor-frame-features.mjs`；五视角深度、worst-view 和 CVaR 详见 `lib/view-conditioned-evaluator.mjs`。Qwen 不读取三维坐标以生成位置，也不属于在线推理的输入；历史奖励 MLP 只用于有重排的对照组。

## 连续策略与损失

对同一标签顺序，网络输出锚点局部布局 `μθ(x) ∈ R^(N×6)`，每行依次为 `local_u, local_v, local_normal_distance, log_size_x, log_size_y, log_size_z`。当前实现采用高斯对角标准差 `[0.15,0.15,0.10,0.18,0.18,0.18]`，默认固定；可学习六维 log-std 仅作为消融。

```text
log πθ(y|x) = -1/2 Σ_(i,k) [((y_ik−μθ,ik)/σ_k)^2 + 2 log σ_k + log(2π)]
rθ(y) = log πθ(y|x) − log πref(y|x)
m_d = (score_A,d − score_B,d)/4
L_d = λ_d |m_d| softplus[-β sign(m_d) (rθ(yA)−rθ(yB))]
L_pref = Σ_d L_d + λ_KL KL[πθ(·|x) || πref(·|x)]
L_train = L_pref + λ_sup L_v10-supervised + λ_tail L_center-tail + λ_safe L_geometry-safe
```

`d=overall` 用 `λ_DPO`；另外六维用 `λ_multi × weight_d`。绝对分差不大于 0.025 的维度为 tie，其偏好损失及梯度为零。`πref` 是哈希固定的原始 v10，训练时不更新。LoRA 默认 rank 4，19 个矩阵共 7,648 个矩阵参数，加 28 个 router/expert/decoder bias 参数共 7,676；可学习方差消融再增加 6 个。见 `lib/mdpo-continuous-policy.mjs`、`lib/mdpo-lora.mjs`、`scripts/train-v10-mdpo.mjs`。

为绘制可信的逐维验证损失曲线，从 train33 每个 OBJ 的 6–12 对偏好中按候选 ID 哈希固定留出一对（正式完整数据共 33 对），余下偏好对产生梯度。每轮只对留出对计算七维 MDPO 损失，不回传其 Qwen 评分；该曲线明确标为 **train33 留出偏好验证**，不可冒充 val11。val11 的七维 Qwen 六图结果是独立评分与激活门控，不属于逐轮 MDPO 验证损失；val11 人工中心几何诊断同样不得回传梯度。

每个正式候选同时保存 19 个 LoRA 矩阵和 28 个 bias 的逐路径更新量、模块汇总、参考网络数值参数量、可训练参数量与比例，并在一个固定 train33 图上比较“训练后 LoRA+bias”与“同 bias 但消融 LoRA”的 6D 输出最大变化。81-grid 选择与终态审计要求 GNN2、Transformer、MoE router 和四个专家解码器均至少有矩阵更新，且消融输出变化非零。

训练结束后，冻结 v10 与候选 v10-MDPO（均关闭末端奖励重排）在实际参与训练的 33 个 OBJ 上使用固定五视角统一评价器，保存 `PCK_005, PCK_010, OLR, LCD, avg_leader_length, overlap_pairs, occluded_points, intersections, quality_score` 的 baseline、candidate 与 delta。该 train33 表只描述训练集拟合，不代替 val11 激活或 test11 最终泛化结果。

安全评价独立于 Qwen，交叉、穿透、网格相交及最差视角越界的零容忍项先过滤训练候选。val11 激活门控以 `Δ aesthetic ≥ 0.02` 和 `Δ composition_harmony ≥ −0.01` 为主，并要求 PCK、OLR、LCD、遮挡、穿模、网格相交、最差视角越界、文字清晰度及引导线清晰度符合代码中的固定非退化阈值。安全阈值不得为迁就候选而调低。见 `lib/mdpo-collection.mjs` 和 `lib/mdpo-activation-gate.mjs`。

`no_reference_kl` 消融同时移除偏好比值中的冻结参考 log-prob 与显式 KL；只将 `lambdaKl` 设为零不构成无参考消融。其余正式候选仍使用冻结 v10 参考策略。

## 数据路径与禁止泄漏

| 阶段 | 数据划分 | 允许的操作 | 禁止的操作 |
| --- | --- | --- | --- |
| 六图安全候选与 Qwen 七维偏好 | train33 | 6–12 对/物体、198–396 对、真正更新 LoRA | 把 test/val 变成偏好对、Qwen 直接生成坐标 |
| 超参数搜索与激活判决 | val11 | 81-grid、11 个样本×四组、固定 seed/模型/prompt、真实六图与确定性指标 | 把 val11 分数回传梯度或用 test11 挑模型 |
| 九组消融 | train33/val11 | 同协议训练、val11 四组结果和 rank/β 敏感性 | 更改固定数据划分或复用 test 选参数 |
| 锁定后的最终报告 | test11 | 一次四组评估、44 条不可变样本证据、九项统一 JSON/CSV | 二次测试、依据测试重训或重新激活 |

四组固定为 `v10_no_rerank`, `v10_historical_rerank`, `mdpo_no_rerank`, `mdpo_safe_rerank`。是否把 Qwen 偏好学进 v10 参数，核心只比较第 1 与第 3 组；后两种 rerank 模式应保留同一个历史奖励模型哈希。四组逐样本核对同一 seed、生成协议、Qwen 模型、prompt、视角和历史奖励哈希；完整 44 条原始 Qwen 记录必须与不可变四组报告逐字对应。真正部署还需完整 train33、81 个权重和 val11 报告、不可变四组报告、全部门控、原始 v10 备份及奖励模型前后哈希一致。test11 完全不参与激活。

## 命令与结果位置

页面的 v10-MDPO 区现在提供“选择模型并设置训练参数”控制台，使用 `/api/mdpo-training-control` 的 GET 获取 train33 正式审计、活动原始 v10 哈希、正式流水线占用和最近任务日志；POST 提交学习率、β、λ、LoRA rank、随机种子、训练轮数、逐维权重等受限参数，只运行一次自定义独立诊断训练。服务端拒绝未知参数、未完成的 train33、缺失/不匹配的不可变数据审计、参考模型不一致及与正式流水线并发的请求。任务输出于 `experiments/mdpo/manual_runs/<run_id>/`，候选始终为 diagnostic-only，绝不通过此按钮绕过 81-grid、val11 激活门控或提前运行 test11；刷新状态可查看日志末尾。运行中的原始服务必须在安全的采集空窗期重新启动后才能加载新 API，不能为显示按钮而中断仍在采集的 Qwen 评分回执。

长任务每小时检查一次；中断只恢复已有经哈希验真的记录。正式训练 checkpoint 保存并恢复完整随机状态、历史最优权重、早停计数和已核验的 checkpoint 哈希链；81-grid 与九组消融会从该训练目录的最后一个有效 checkpoint 断点恢复。每个候选模型和 checkpoint ledger 双文件不可变发布，且训练中 OBJ 参考和 train33 数据哈希不得变化。

1. `npm run audit:mdpo-data`：只在 train33 完整后进行严格数据审计；持续采集进度保留在 `dataset_audit.json`，正式报告写入不可覆盖的 `dataset_audit_final.json`，终态审计按 train33 文件哈希和样本/候选/偏好对统计重新核验。
2. `npm run sweep:mdpo`：81 组训练；`experiments/mdpo/sweep/sweep_ledger.json`。
3. `npm run evaluate:mdpo-val11-sweep`：顺序四组六图 val11；不可变报告位于 `experiments/mdpo/val11_reports/`。
4. `npm run select:mdpo`：从完整 81-grid 中仅依 val11 选模型。若全部被拒，同时不可变发布 `experiments/mdpo/hyperparameter_selection.json` 和 `experiments/mdpo/val11_rejection_report.json`；拒绝报告包含 81 条拒绝原因、原始 v10 和历史奖励模型哈希，并禁止运行 test11。
5. `npm run ablate:mdpo`，随后 `npm run evaluate:mdpo-ablations`：九组消融训练、四组 val11 与 JSON/CSV 报告。
6. 仅当选择门控全部通过时执行 `npm run activate:mdpo`；否则原始 v10 继续运行，并明确记录最佳被拒候选。
7. 仅在正式激活并锁定后执行 `npm run evaluate:mdpo-test11`；该命令不能覆盖已有最终 test11 证据。
8. 完成所有正式证据后运行 `npm run audit:mdpo-browser` 生成不可变正式截图与无错误控制台报告；`npm run test:mdpo-policy` 和只读 `npm run audit:mdpo-final` 完成最终技术审计。当前尚未齐备时，正式浏览器命令必须拒绝生成终态文件。

### 可恢复的全流程编排

正式 train33 采集运行时，可以用采集器 PID 启动：

```powershell
npm run pipeline:mdpo -- --collectorPid <PID>
```

编排器 `scripts/run-v10-mdpo-full-pipeline.mjs` 只在该采集器退出且 `train_pairs.json` 通过完整 33/33、198–396 对严格校验后继续。它按上述固定顺序执行数据审计、81-grid、完整 val11、选模、九组消融及终态验收，并把状态写入 `experiments/mdpo/pipeline/full_pipeline_ledger.json`。每个长阶段单独保存 stdout/stderr，约每小时写一次进程心跳。

编排器不提供强制激活开关，也不降低任何门控。如果 `deployment_eligible=false`，它必须验证不可变拒绝报告、保留原始 v10，并跳过激活与 test11；只有 `deployment_eligible=true` 且九组消融证据完整时，才允许原子激活、锁定并运行一次 test11。任何阶段退出码非零或权威产物缺失都会立即停止后续阶段。

训练实现将目标明确拆分并逐 epoch 保存：七维 MDPO loss、原始 v10 中心/尺寸/人工风格/引导线方向监督、中心误差长尾 CVaR、独立 `lambdaSafe` 几何安全目标及 reference KL。`lambdaSafe` 对应 weighted-main、worst-view、CVaR、stereo、字体清晰度和引导线交叉的确定性可微评价，不能被 Qwen 美学分抵消。

激活后的 `experiments/layout_model.json` 才可称为活动 v10-MDPO；训练候选始终标记 `diagnostic_only_requires_full_val11_gate`，烟雾测试更不是已部署模型。若 81-grid 所有候选都未通过 val11，保留原始 v10，输出拒绝报告，严禁谎称 MDPO 或 v11 已部署。

## 截至 2026-09-22 的真实状态

当前活动模型仍是原始 v10；历史奖励 MLP 未改。train33 的后台真实 Qwen 数据收集尚在进行中，尚无正式 81-grid、11 样本四组 val11、正式消融及锁定后 test11。因此本文件不能被解读为这些实验已经完成。浏览器初步截图和策略单测只能证明当前代码能显示待完成状态，不能代替正式实验结果。
