# 3D 标签生成系统与实验设计

> 本文包含历史设计建议。2026-09-18 已完成的监督训练是四风格 MLP，而非四类 CNN/GNN/Transformer 专家训练。自动生成多布局、原始图加五视角六图评分、LLM 偏好对、36→32→1 奖励网络、val 门控和 test11 最终确认的闭环已经完成真实外部实验：3 个 train 样本、24 个评分、15 条偏好；奖励候选因 val 退化而未激活。当前权威状态见 [真实 LLM 偏好学习报告](真实LLM偏好学习报告_2026-09-18.md)、[程序架构图](程序架构图.md)、[固定标签五视角训练与偏好架构](固定标签五视角训练与偏好架构.md) 和 [人工调整后标注来源与尺寸泄漏审计](人工调整后标注来源与尺寸泄漏审计.md)。

## 1. 当前系统边界

系统将任务拆成四个阶段：

```text
干净 OBJ 输入
  -> 标签候选生成器
  -> 分组 / 双目 / 尺寸策略 + 退火优化
  -> JSON 标注 + 带标签 OBJ + WebGL 可视化
  -> 人工评价 / GPT 维度评分
```

当前数据中的 `Obj-O/*.obj` 是人工调整后的导出结果，不是纯净输入：其中同时存在物体组、`label_*` 标签面板、`leader_*` 引导线和 `anchor_region_*` 材质。实际检查发现，`anchor_region_*` 在该数据集中用于物体本身的面，不能按标签层删除。因此程序读取样本时会重建 clean OBJ：

- 删除 `label_*` 和 `leader_*` 组；
- 保留 `anchor_region_*` 物体面，仅删除 `label_*`、`leader_*` 组及对应材质；
- 只保留物体面并重新索引顶点；
- 原始文件不覆盖，输出标签另存为 `_labeled.obj`。

## 2. 数据划分

`experiments/dataset_manifest.json` 是固定划分清单。按照类别分层、样本编号自然排序后采用 3/1/1 划分：

| split | 数量 | 每类数量 |
|---|---:|---:|
| train | 33 | 3 |
| val | 11 | 1 |
| test | 11 | 1 |

该划分适合当前只有 55 个样本的验证阶段。最终论文实验仍建议补充跨类别测试：训练类别与未见类别分开，避免只学习类别名称或固定几何模板。

批处理入口为 `npm run artifacts -- --split test ...`，会把 clean OBJ、标签 JSON、带标签 OBJ 和元数据写入 `experiments/artifacts/`；`npm run dataset:validate` 会对全部 55 个样本执行几何与展示层清洗检查。

## 3. 标签生成基线

当前内置基线包含：

1. `JSON 标注映射`：把现有 Annotation JSON 的 `anchor`、`label.center`、`label.box_size`、`leader_line` 作为候选结果，用于检查数据匹配和可视化链路。
2. `包围盒演示`：无 JSON 或本地 OBJ 调试时生成一个最小标签，验证输入、渲染和 OBJ 输出链路。
3. `标签分组`：
   - `全部标签`：保留所有候选；
   - `同语义只保留一个`：同名部件只选一个代表，例如四条腿只标一条；
   - `对称候选择优`：当同语义候选在左右方向有足够跨度时保留两侧，否则保留一个。
4. `尺寸策略`：相对物体比例、固定世界尺寸、随视距调整。
5. `模拟退火优化`：在虚拟左右相机下计算标签重叠、引导线交叉、视野越界、锚点距离和双目视差损失，使用温度下降与随机候选扰动搜索布局；每个标签会记录初始分数、最终分数、迭代次数和约束项。`规则式基线`保留为对照。

当前实现已经包含可复现的无依赖模拟退火优化器，但仍属于研究基线，不应直接当作最终论文模型。随机种子和迭代次数可在网页“快速实验工具”中调整；仍需要通过人工评分验证“只标一条腿”“对称物体两侧分布”等假设。

网页会在生成结果后自动计算主视角指标，并同步写入标签 JSON、评价记录和批量产物：可读性代理分数、语义覆盖分数、标签重叠对数、视野越界比例、引导线交叉数、锚点覆盖率和双目视差。它们是几何/投影代理指标，用来辅助人工评分，不替代测试员偏好。

对清单内的监督样本，人工 Annotation JSON 的标签数量、顺序、ID、文字、锚点和语义关联作为固定标签契约进入候选流程；人工调整后的最终中心与尺寸只作为监督目标，不进入无泄漏 v4 的 51 维输入。无人工 JSON 的自定义 OBJ 才完全依赖 clean OBJ 部件组和几何特征生成候选。人工最终布局同时作为 reference 计算 `manual_comparison`，但不会在推理时直接复制到输出。

为便于和已发表的双目 3D 标签布局工作对齐，系统同时输出三项论文风格指标：`DBV`（Double Vision Degree，双目重影比例）、`OLR`（Overlap Ratio，标签重叠比例）和 `LCD`（Line Crossing Degree，引导线交叉程度）。BinoForce 论文明确使用 DBV、OLR 和 LCD 评价双目重影、标签重叠和引导线交叉，并将 Hedgehog 作为对比方法之一；本系统采用同名指标作为工程化近似，不声称复现 BinoForce/Hedgehog 的完整算法。citeturn0search0turn0search2

## 4. 双目目标

网站当前把“双目一致性”作为显式策略和评分维度，并将约束写入每个标签的 `view_constraints`。下一步模型应为左右视角分别定义可见性和遮挡损失：

```text
L = λ1 * overlap
  + λ2 * occlusion_left
  + λ3 * occlusion_right
  + λ4 * disparity_instability
  + λ5 * label_distance
```

建议先用双目静态相机对比实验，再决定是否移植到 VR：当前阶段网页可视化足以支持算法迭代、标注检查和评分收集；只有当视差、头部运动和实时渲染成为研究变量时再做 VR 版本。

## 5. 图模型和专家模型建议

将每个标签候选作为节点，将以下关系作为边或约束：

- 同语义重复边；
- 空间重叠边；
- 引导线交叉边；
- 双目可见性边；
- 对称部件边；
- 标签与锚点距离边。

推荐的可替换中间模型：

```text
候选节点特征
  -> 图编码器 / MLP scorer
  -> 专家偏好头（可读性、简洁性、对称性、双目稳定性）
  -> 退火或 beam search 选择标签集合
```

专家可以不是不同的基础模型，而是不同的偏好头或不同权重向量。这样先能做可解释的消融：规则式、单一偏好、混合专家、MDPO 优化后的模型。

综合模型 v1 的路径是“候选节点特征 → FNN、GNN、CNN、Transformer 四个专家并行编码 → MoE 路由器融合 → 模拟退火解码”。配置保存在 `experiments/model-v1.json`，实现位于 `lib/model-adapter.mjs`。四个专家不是互斥选项，而是共同参与 v1 预测；当前是初始化权重，网页训练按钮会在本地训练偏好评分器并用于候选重排序。

新的布局监督训练入口为 `npm run train:layout`。它不做 semantic-once 语义去重，而是使用 train split 的全部人工部件标签作为监督目标，同时学习每个类别的标签数量和 group 先验、每个部件的标签中心偏移与尺寸；val split 只用于验证，test split 只用于推理。当前生成的 `layout_model.json` 会记录 train/val MSE、类别标签数量统计、group priors、风格 expert 数量和训练超参数。这样 test 中不会把每个细碎 mesh group 都误当作标签，也不会把人工 test 标签位置直接复制给模型。

## 6. MDPO / 偏好训练数据格式

每条偏好样本建议保存：

```json
{
  "sample_id": "38635",
  "prompt": { "category": "Chair", "view_policy": "binocular" },
  "chosen": { "labels": [] },
  "rejected": { "labels": [] },
  "human_scores": {
    "readability": 4,
    "coverage": 3,
    "occlusion": 5,
    "balance": 4
  },
  "comment": "四个脚标一个即可"
}
```

先收集人工两两偏好，再训练偏好模型；不要让 GPT 评分直接替代人工标签。GPT 评分适合做一致化维度分析、发现风险和生成改进建议，最终奖励仍应由人工偏好和任务指标共同构成。

网页中的候选 A/B 按钮会把两次不同策略的输出保存为 `chosen` / `rejected`，后端写入 `experiments/preferences.jsonl`。这为 MDPO 或奖励模型提供偏好对；人工 1–5 分仍作为辅助连续信号。

本地还提供 `npm run train:preference`：它使用偏好对中的主视角/双目几何指标训练一个可解释的偏好评分器，输出 `experiments/preference_model.json`。网页训练按钮调用同一个本地入口。服务端发现该文件后，会在 `/api/generate` 中生成多个退火种子候选，用偏好分数重排序，并返回 `metrics.preference_score` 和 `selection_trials`。这个版本是 MDPO 前的偏好模型基线；真正的 MDPO 或深度框架训练仍应在积累足够人工偏好后进行。

## 7. 规则式基线与学习模型对比

必须使用同一 test split、同一标签库、同一相机设置和同一输出格式比较：

- 规则式：固定分组、固定尺寸、碰撞约束、贪心或退火；
- 学习式：图模型 / 专家偏好模型；
- 偏好优化式：基础模型 + MDPO；
- 指标：人工总体评分、可读性、遮挡、双目稳定性、标签数量、推理时间。

建议报告均值、标准差、每个类别结果和配对显著性检验。只有在 test split 上优于规则式，才能声称学习偏好带来收益。

## 8. GPT-5.5 评分 API

后端提供 `POST /api/generate` 和 `POST /api/score`。前者在本机完成 OBJ 清洗、候选模型适配器、分组、双目/尺寸策略、退火解码和主视角指标；后者只负责可选的 GPT 视觉评分。服务端读取环境变量：

```powershell
$env:OPENAI_API_KEY = "你的 API Key"
$env:OPENAI_MODEL = "gpt-5.5"
node server.mjs
```

请求体由网页自动发送，核心字段包括 `sample`、`strategy`、`labels`、`human`。接口使用结构化 JSON Schema，输出 1-5 分的 `readability`、`coverage`、`occlusion`、`balance`、`binocular_consistency`、`size_consistency`、`group_economy` 和 `overall`，以及 `rationale`、`risks`、`suggested_changes`。

网页请求还会附带左右 WebGL 视口截图，使 GPT 能同时参考布局坐标和实际遮挡/可读性外观；评价日志不保存截图，服务端评分请求体上限为 64 MB。没有配置 API Key 时接口会返回明确的 `OPENAI_API_KEY_MISSING`，不会伪造 GPT 评分。所有 API Key 只放在服务端环境变量中，不写入前端。
