# 人工调整后标注来源与输入泄漏审计

## 标注来源（2026-09-18，项目内实测）

`experiments/dataset_manifest.json` 共列出 55 个样本（train 33、val 11、test 11）。全部 55 份 `target.annotation_json` 均明确标记：

```json
{"version":"after_mannual_adjust","layout_type":"manual_adjusted"}
```

`after_mannual_adjust` 是原数据中的实际拼写，不应擅自改写文件。406 个标签全部含 `label.center` 与 `label.box_size`；训练脚本经 `annotationsToLabels` 读取它们，再用 `targetVector` 构建中心相对锚点的偏移及面板尺寸六维监督目标。`Mutiviews/*.png` 没有进入训练监督目标；网页中的“原始模型图”是移除已有标签与引导线网格后的 OBJ 渲染，不是数据集的“人工调整前布局图”。

这能证明**当前项目使用的是数据集自称“调整后”的 JSON**；仅凭这些文件无法独立复原人手调整过程，也没有发现与之配对的调整前坐标 JSON，不能声称做了调整前→调整后的逐操作监督。

## 已发现的旧版实验限制

旧版 `fixedCandidatesFromManual` 虽不把人工最终 `label.center` 作为候选中心，却把人工最终 `label.box_size` 放进了候选；`multiViewLayoutFeatures` 又使用候选尺寸作为网络输入及五视角投影框特征。因此旧 v2 / v3 模型的尺寸回归和相关验证指标含有输入信息泄漏，不能作为“从纯几何独立预测人工最终尺寸”的证据。保留旧文件用于历史复现，不修改权重或隐瞒这一限制。

新候选使用 `fixedCandidatesWithoutTargetLayout`：输入只保留人工确定的数量、ID、文字、锚点、语义关联，并从固定标签文本长度与物体几何尺度确定初始面板尺寸；中心从清理后的 OBJ 几何/固定锚点初始化。人工调整后的中心及尺寸只用作监督目标。`npm run test:layout-provenance` 对 55 个样本、406 个标签证明：修改任何目标的最终中心和尺寸时，候选与 51 维输入逐项不变，监督目标相应改变。

无泄漏 v4 候选另存 `experiments/layout_model_provenance_safe_candidate.json`，训练报告另存 `experiments/layout_training_provenance_safe_report.json`。验证集选择融合比例时必须使用相同的无泄漏候选，分别评估无模型、旧模型和新候选；未通过 val 门控不能替换 `experiments/layout_model.json`。历史 v2 结果与无泄漏结果使用不同输入协议，不可直接作为同口径对照。

## 本轮训练与独立验证结果

2026-09-18 使用 80 epoch、seed 17 训练了完整的新候选；`experiments/multiview_provenance_safe_inference_selection.json` 在冻结的 val11 上搜索 35 种融合比例。以下均在**同一无人工最终尺寸输入**下对照，五视角能量越低越好：

| split | 无模型 | 旧 v2（改用无泄漏输入） | 新 v4 候选 |
| --- | ---: | ---: | ---: |
| val11 | 2.381636 | 2.271909 | **2.246909** |
| test11（门控之后仅一次最终确认） | 2.386455 | **2.392636** | 2.537273 |

val 决定的配置是 `center_blend=0`、`size_blend=0.15`，新候选对旧 v2 的 val 能量约改善 1.10%，所以文件中 `validation_gate.status=accepted`；但 test11 相比同口径旧 v2 恶化约 6.04%，不能声称新模型在未见样本上更好。它**尚未激活**，当前 `layout_model.json` 仍是原 v2；不能用 test11 反过来调整本轮融合比例或训练参数。后续若要稳健改进，应在 train/val 侧扩充数据或制定预先确定的交叉验证方案，再用新的未见测试集确认。
