# MoE1 三风格布局架构补充与实施记录（2026-09-29）

## 1. 当前项目架构阅读结论

当前系统已经不是早期的二维规则布局，而是固定标签契约下的三维外部标签实验平台：

- `lib/candidate-generator.mjs` 只保留人工标注中的标签数量、顺序、ID、文本、锚点和部件绑定；训练输入不读取人工调整后的标签中心与尺寸，避免尺寸/位置泄漏。
- `lib/spatial-style-features.mjs` 从 clean OBJ 和标签集合中提取纯三维空间特征，包括空气体素、局部密度、标签间距、引导线长度、方向分布等。
- `lib/anchor-frame-features.mjs` 与 `lib/heterogeneous-layout-graph.mjs` 为 v10 建立锚点局部坐标系与 anchor-label / label-label 异构图。
- `lib/layout-model.mjs` 执行 DGCNN 几何特征 + 51D 局部标签特征 + 异构 GNN + Transformer + MoE 的推理。
- `lib/layout-optimizer.mjs` 负责五视角安全能量、模拟退火、引导线交叉修复、越界/重叠/遮挡/可读性等评价。
- `scripts/train-3d-human-style-layout-model.mjs` 负责 v9/v10 监督训练；`scripts/train-v10-mdpo.mjs` 负责偏好/LoRA 风格微调候选。

因此，本轮不重写主线，而是在现有 v10 主线上补充“物体轮廓驱动的三风格 MoE 路由 + 三类初始化专家”，让后续监督训练、无监督伪标签和 MDPO 都能共享同一套风格定义。

## 2. 将原始需求细化成可执行定义

### 2.1 MOE1：球状/环状布局

适用对象：投影轮廓相对紧凑、三维包围盒不明显细长、锚点角度分布较均匀的物体。

实现细节：

1. 从 clean OBJ 或包围盒采样点投影到主视角，构造二维轮廓点云；
2. 对点云计算凸包、投影包围框、径向均值、径向变异系数；
3. 按锚点相对轮廓中心的角度排序；
4. 将标签中心排布在轮廓外侧的椭圆环上；
5. 用最小角距约束缓解相邻标签挤在同一圆弧；
6. 标签中心会被限制在视野内，避免初始化直接越界；
7. 输出 `layout_style_expert=spherical`、弧角、路由概率和轮廓特征，供审计与后续训练使用。

### 2.2 矩形布局

适用对象：三维或二维投影明显长条形的物体。

实现细节：

1. 根据主视角轮廓点云得到包围矩形；
2. 每个标签根据锚点投影离矩形四边的距离分配到 left/right/top/bottom；
3. 同一边按主方向排序并均匀分布；
4. 矩形边距根据物体大小和标签半宽/半高自适应；
5. 标签中心限制在视野内；
6. 输出 `layout_style_expert=rectangular` 和 `rectangular_side`。

### 2.3 围绕布局

适用对象：形状不规则、锚点集中、难以形成整齐弧线/矩形边的物体。

实现细节：

1. 不强制同边对齐，也不强制相邻标签处在同一圆弧；
2. 每个标签按自身锚点相对轮廓中心的方向向外推；
3. 主要保证围绕物体、不过近、不越界；
4. 后续交给五视角能量和模拟退火解决重叠/交叉。

### 2.4 多维度风格打分和模糊区域处理

当前实现使用 soft routing，而不是硬阈值：

- `projected_aspect`：主视角轮廓长宽比；
- `aspect_3d`：三维包围盒长宽高比；
- `contour_regularity`：投影轮廓径向变异系数归一化后的规整度；
- `anchor_angular_entropy`：锚点方向分布熵；
- `anchor_radial_uniformity`：锚点径向距离一致性。

三类专家分数归一化成概率。处在类别中间的样本不会被强行切断，而是保留概率分布，训练时可作为 MoE router 的软目标。

### 2.5 无监督能量与伪标签

现有 `layout-optimizer` 已覆盖需求中列出的核心安全项：

- 标签重叠：`olr` / `overlap_ratio`；
- 视野越界：`overflow_ratio`；
- 遮挡：`object_occlusion`、`label_object_occlusion`、`object_penetration`；
- 引导线交叉：`lcd` / projected leader crossings；
- 锚点距离或人工引导线长度范围：`anchor_distance` 或 `leader_length_range`；
- 可读性：`text_pixel_height`、`text_fit_ratio`、`text_clarity`；
- 标签与标签距离/方向密度：`directional_allocation_mismatch`、`directional_concentration_excess` 和空间特征中的 spacing；
- 标签与物体距离：空间 clearance 与深度穿透代理。

本轮新增的 MoE 风格初始化会进入 `optimizeLabels(..., { layoutStyle: 'auto', optimizer: 'annealing' })` 的初始布局，然后由模拟退火继续寻找低能量伪标签。

### 5.4 扰动候选增强

`lib/mdpo-candidate-perturbation.mjs` 已在原有 compact/spacious/大小缩放/切向偏置基础上补充四类与本需求直接对应的扰动：

- `increase_label_gap`：增大标签间隙和局部切向分散；

## 6. 人工评分—LLM 风格评分显著性验证流水线

新增 `scripts/evaluate-moe-style-llm-validation.mjs`，把原始设想中的“人工自然描述打分 → LLM 多视角打分 → 显著性检验”拆成三步：

```powershell
npm run prepare:moe-style-llm
npm run run:moe-style-llm -- --limit 11
npm run validate:moe-style-llm -- --humanScores experiments/moe_style_human_score_template.csv --llmScores experiments/moe_style_llm_scores.json
```

第一步会生成：

- `experiments/moe_style_human_score_template.csv`：人工填写 spherical / rectangular / surround 的 1-5 分模板，同时附带几何先验分；
- `experiments/moe_style_llm_prompt_manifest.json`：每个样本的五视角图片路径、提示词和 JSON schema。

第二步会把 main/right/left/up/down 五张视角图发送给本地 Ollama/Qwen3-VL，并要求返回三风格 1-5 分、选择结果、置信度和理由。该步骤需要本机 Ollama 服务可用。

第三步会对人工分与 LLM 分做验证：

- 每个风格维度的 Pearson 相关；
- 每个风格维度的 Spearman 秩相关；
- 配对 t 检验的系统偏差近似；
- dominant style 一致率。

建议门槛写入报告：样本数不少于 10、三维度 Spearman 均值不低于 0.55、主导风格一致率不低于 0.60，且没有明显系统性偏差时，才把 LLM 作为扩展数据前置打标工具。

## 10. 多专家布局竞争、几何—LLM 联合选择与 router 反向优化

根据新增要求，已补充“同一个样本由多个专家分别生成布局，再联合几何质量与 LLM 风格分数选择专家”的训练前选择阶段。

新增脚本：

- scripts/generate-moe-expert-layouts.mjs：每个样本分别生成 spherical、rectangular、surround 三个专家布局；
- scripts/select-moe-expert-by-geometry-llm.mjs：结合五视角几何质量和 Qwen 风格分数生成软 router target。

运行命令：

```powershell
npm run generate:moe-expert-layouts -- --split train --iterations 120 --output experiments/moe_expert_layouts_train33.json
npm run select:moe-expert -- --experts experiments/moe_expert_layouts_train33.json --llm experiments/moe_style_llm_scores.json --output experiments/moe_expert_selection_train33.json
npm run train:layout:v10:expert-selection
```

联合选择定义：

- 几何质量分：由 3D OBJ 生成的五视角相机投影结果计算，包含多维质量、文字可读性、标签重叠、引导线交叉、越界、遮挡、穿透和肉眼可见线重叠；
- 当前专家选择只使用五视角几何质量，避免把尚未完成人工—LLM 显著性验证的风格先验直接当作最终标签；
- Qwen 风格分仍保留在候选偏好和后续 LoRA/MDPO 阶段；
- router target：几何质量经过 temperature-softmax 得到概率，不做硬 one-hot，从而保留模糊样本的多专家梯度。

训练脚本读取 expert_selection_train33.json 后，router 的交叉熵目标使用五视角几何质量概率；如果没有该文件，则回退到轮廓几何路由。已用 1 epoch smoke test 验证 33/33 个 train 图接入联合选择，MoE router 参数发生真实更新。

## 13. 肉眼可见的引导线重叠损失

新增 `lib/layout-optimizer.mjs` 的可见引导线重叠检测：不再只判断像素级精确相交，而是对投影后的两条引导线计算线段距离和沿主线方向的重叠长度；当两条近似平行的线在屏幕上距离小于可视阈值且重叠长度超过 22% 时，记为 `visible_leader_overlap`。

- 主视角进入模拟退火能量，权重为 3.6，并采用主视角 0.40 的权重；
- 其他视角仍参与五视角平均，但不会用单一侧视角覆盖主视角安全性；
- `evaluateLayout` 新增 `visible_leader_overlap_ratio` 和 `multi_view_worst_visible_leader_overlap`；
- 专家联合选择的几何分会额外惩罚该指标；
- test11 界面专家卡片显示“线重叠”指标；
- `scripts/test-visible-leader-overlap.mjs` 已验证平行且肉眼重叠的引导线会比空间分离布局得到更高能量。
